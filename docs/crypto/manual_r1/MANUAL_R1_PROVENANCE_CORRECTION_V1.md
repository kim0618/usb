작성 2026-09-28. **기존 MANUAL-R1 문서 4편은 수정하지 않았다.** 역사적 기록으로 보존한다.
이 문서는 그 결론이 왜 사용자 discretionary trading에 적용될 수 없는지를 별도로 적는다.

## 1. 무엇이 잘못됐나

MANUAL-R1은 Paper 원장의 완료 거래 **17건 전체를 사용자의 재량 매매로 간주**하고
`NO_VERIFIED_EDGE`를 선고했다.

**그 전제가 틀렸다.** 사용자 확인 결과 실제 사용자 판단 거래는:

| | 건수 |
|---|---|
| 완료된 사용자 거래 | **1** (거래 17, net +330.75) |
| 미결 사용자 포지션 | **1** (SHORT 0.921 @ 84038.20) |

나머지는 SAFE MAX 검증, sizing smoke, 50x 검증, 배포 smoke 등
**개발·검증 과정에서 운영 계좌에 남은 주문**이다.

### 이것은 제 오류다

증거는 작업 당시에 이미 있었다.

| 있던 증거 | 내용 |
|---|---|
| `CRYPTO_D4_1_SAFE_SIZING_V1.md` §1 | "실측(운영, 2026-09-24): 포지션 진입 **1.082 BTC** ... 전량 청산 시도 ... NO_LIQUIDITY" |
| `CRYPTO_D4_1_SAFE_SIZING_V1.md` §8 | "`paper-server-001` 은 **사용자 실사용 계좌**다 ... 개발 smoke는 임시 격리 인스턴스에서" |
| 배포 메모리 | "**MAX 0.085 체결 성공** ... MAX+1스텝은 INSUFFICIENT_MARGIN" |
| 배포 메모리 | "이번에 **내 smoke 2건** 확인 후 cleanup 완료 → 전체 16건 이력 보존" |

**나는 원장을 열기 전에 이 문서들을 확인하지 않았다.** provenance를 묻지 않고
"수동 계좌의 거래 = 사용자 거래"로 건너뛴 것이 오류의 전부다.

D4.1 문서 §8이 이미 규칙을 적어 두었다:

> **4. 기존 거래를 개발 테스트라고 가정하지 않는다.**

이 규칙은 양방향이다. 나는 반대 방향으로 어겼다 -
**기존 거래를 사용자 거래라고 가정했다.**

## 2. 왜 원장만으로는 알 수 없었나 (구조적 원인)

원장을 아무리 정확히 읽어도 provenance는 나오지 않는다.

| 확인한 것 | 결과 |
|---|---|
| `reason` 필드 | **35개 FILL 전부 `MANUAL`** |
| `request_id` 형식 | **전부 `open-<ts>-<seq>` / `close-<ts>-<seq>`** - 동일 |
| 주문 경로 | 전부 같은 UI/API 라우트 |
| origin 필드 | **존재하지 않음** |

개발자의 smoke 주문과 사용자의 판단 주문이 **원장에서 구별되지 않는다.**
D4.1 §8이 `SMOKE_TEST` reason을 설계했으나 "**이번 작업 범위에서는 설계만 기록하고 넣지 않았다**"고
적혀 있다.

**따라서 이것은 분석자의 부주의이면서 동시에 시스템의 공백이다.**
provenance 계약(`docs/crypto/manual_r2/MANUAL_R2_PROVENANCE_CONTRACT_V1.md`)이 필요한 이유다.

## 3. 기존 수치의 상태

**숫자 자체는 틀리지 않았다.** 회계는 원장 자체 누적값과 3항목 모두 정확히 일치했고,
그 검증은 지금도 유효하다.

| 기존 수치 | 값 | **상태** |
|---|---|---|
| 완료 거래 17건 | - | **유효** (원장 사실) |
| 생애 실현 net -413.86 USDT | - | **유효하나 해석 무효** - 혼합 집계 |
| 승률 23.5% / PF 0.456 / MDD 98.8% | - | **사용자 성과로 사용 금지** |
| 청산 1회 -600.56 | - | **유효** (원장 사실), 귀속은 UNKNOWN |
| 수수료가 gross의 2.75배 | - | **유효하나 해석 무효** - 대부분 테스트 주문의 수수료 |
| 리셋 3회 / 7,456 USDT 투입 | - | **유효** |
| 미결 포지션 +852.20 미실현 | - | **유효**, 사용자 거래로 확인됨 |
| 중앙 보유 0.54분 | - | **테스트 거래의 특성이지 사용자 습관이 아니다** |

**가장 잘못 읽힌 문장**: "체감과 원장이 다릅니다."
사용자는 자신의 거래 2건을 근거로 수익을 체감했고, **그 2건은 실제로 둘 다 플러스다**
(+330.75 실현, +852.20 미실현). 체감이 틀린 것이 아니라 **내가 남의 거래를 사용자 것으로 합산**했다.

## 4. H1 / H2 / H4 재판정

| 가설 | 내용 | **재판정** |
|---|---|---|
| **H1** | 사용자는 하락을 예측하지 않고 추격한다 | **CONTAMINATED** |
| **H2** | LONG과 SHORT의 진입 시점이 구별되지 않는다 | **CONTAMINATED** |
| H3 | "상승 둔화 포착" 모양이 없다 | **CONTAMINATED** |
| **H4** | 사용자는 기다리고, 기다린 거래가 이겼다 | **NOT_EVALUABLE** |
| H5 | 손실 구조는 판단이 아니라 비용과 레버리지 | **VALID (단 대상이 다름)** |

### H1 - CONTAMINATED
SHORT 6건 중 **사용자 거래는 1건**(거래 17)이다. 나머지 5건(#2·#4·#10·#12·#14)은
테스트이거나 UNKNOWN이다. "6/6이 control 중앙값 아래"라는 근거는 **표본 1건짜리 주장**이 된다.

### H2 - CONTAMINATED (가장 중요한 정정)
"17/17 전부 control 중앙값 아래"는 **개발 테스트 주문의 타이밍**을 관찰한 것이다.
개발자는 화면을 보고 기능을 시험했을 뿐 방향을 판단하지 않았으므로,
LONG과 SHORT의 진입 시점이 같은 것은 **당연한 결과**이지 사용자 행동의 발견이 아니다.

> **"사용자가 LONG/SHORT를 구별하는 정보가 없다"는 결론을
> 사용자 행동에 대한 authoritative finding에서 제거한다.**

### H4 - NOT_EVALUABLE
"45분 넘게 든 2건은 2승, 1분 미만 2건은 2패"에서 45분 이상 2건은 #14(UNKNOWN)와 #17(USER)이고,
1분 미만 2건은 #2·#4(테스트)다. **사용자 거래는 1건뿐이라 보유 시간 비교가 성립하지 않는다.**

### H5 - VALID, 단 대상이 바뀐다
"중앙 보유 0.54분, 1분 이내 9건이 왕복 수수료만큼 잃었다"는 사실이다.
다만 그것은 **개발 테스트가 운영 계좌에 남긴 비용**이지 사용자의 매매 습관이 아니다.

**이 항목은 오히려 provenance 분리의 필요성을 보여주는 근거가 된다**:
테스트 주문 3건(countable)만으로도 net **-101.13 USDT**가 사용자 성과에 섞여 있었다.
