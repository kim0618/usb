## 2. 단계

### S1 - origin 파이프라인 (운영 코드)

| 순서 | 작업 | 파일 |
|---|---|---|
| 1 | `submit_order(origin=...)` 추가, 원장 payload에 전파 | `paper/engine.py` |
| 2 | 주문 요청 모델에 `origin` 추가, `reason` 기본값 제거 | `terminal/api.py` |
| 3 | 테이프 COMMAND 레코드에 origin 실기 | `paper/session.py` |
| 4 | `_origin()`이 이벤트 origin 우선, 없으면 `UNKNOWN_LEGACY` | `paper/analytics.py` |
| 5 | 프론트 주문 호출에 `origin: "USER_MANUAL"` 명시 | frontend |

**S1 완료 판정**: 기존 테이프 재생 **바이트 동일** + crypto 전체 테스트 통과.
바이트가 달라지면 재시작 시 `LEDGER_DIVERGENCE`로 기동이 막히므로 **배포 불가**다.

### S2 - 분석 분리 (운영 코드)

| 순서 | 작업 |
|---|---|
| 1 | `summarize`가 `by_origin_group` 추가 |
| 2 | 성과 화면 기본 필터 = `origin_group == USER` |
| 3 | UNKNOWN은 어느 성과에도 미포함, 별도 카운트로만 표시 |
| 4 | 자본곡선·MDD를 필터 **이후** 계산 |

### S3 - 과거 17건 라벨 (데이터만)

| 순서 | 작업 |
|---|---|
| 1 | `trade_provenance_v1.parquet`를 조회용 side table로 적재 |
| 2 | 화면에서 과거 거래에 origin 배지 표시 |

**원장을 수정하지 않는다.** 라벨은 별도 테이블에 있고, 원장 이벤트는 `UNKNOWN_LEGACY`로 남는다.
MEDIUM·UNKNOWN 13건은 배지에 그대로 `UNKNOWN`으로 나온다. **추정으로 채우지 않는다.**

### S4 - 판단 수집 (사용자가 A를 고른 경우만)

| 순서 | 작업 |
|---|---|
| 1 | `decisions.jsonl` writer (append-only) |
| 2 | 주문 모달에 reason_code·conviction 입력. **기본 선택값 없음** |
| 3 | 자동 부착 필드를 `decided_at_ms` 이전 스냅샷에서 |
| 4 | 미선택 시 주문 버튼 비활성 |

B를 고르면 1·3만. C를 고르면 S4 전체 생략.

### S5 - 개발 테스트 격리

| 순서 | 작업 |
|---|---|
| 1 | 격리 인스턴스 기동 스크립트(별도 포트·run dir) |
| 2 | smoke helper가 `require_origin()` 호출 - 기본값 없음 |
| 3 | 운영 계좌 smoke는 명시 TEST origin 없으면 거부 |

## 3. 배포 순서와 롤백

| 단계 | 배포 | 롤백 |
|---|---|---|
| S1 | 백엔드 + 프론트 **동시**. origin 없는 프론트 + 새 백엔드 = 전부 UNKNOWN | 기존 `backups/` 패턴 |
| S2 | 백엔드만 | 동일 |
| S3 | 데이터 적재 + 프론트 | 데이터만 제거 |
| S4 | 백엔드 + 프론트 | 동일 |

| # | 규칙 |
|---|---|
| RB1 | **재시작 전 원장 sha256 기록.** 재시작 후 동일 확인 |
| RB2 | 사용자 포지션 보유 중 배포 금지. 평탄 상태에서만 |
| RB3 | 배포 검증 smoke는 **격리 인스턴스**에서 |

RB3가 이번 사고의 재발 지점이다. 배포 확인이 운영 계좌에 거래를 남기면 S1~S5가 무의미해진다.
