# C-ATTACK-V0 PIT·실행 계약 V1

작성 2026-09-21. 기계 판독 정본은 `c_attack_rules_v1.json`(canonical sha256 `0e3b4aa5…`)이다. 이 문서는 그 규칙을
사람이 읽을 수 있게 풀고, 코드가 어떻게 지키는지 적는다.

## 1. 시각

| 시각 | 알 수 있는 것 | 쓰는 곳 |
| --- | --- | --- |
| close(D) 이후 | C-M0 후보, 가격·ATR·ADV 버킷, C-E0 status(W_PRIMARY는 close(D) 전 접수분만) | 후보·셀·비용 버킷 |
| open(D+1) | 진입가 E | 진입 |
| 세션 t | 그 세션 OHLC, t 이전에 실행된 분할(F(t)) | 청산 판정 |

D 종가 진입, 프리마켓 가격, 결과를 본 뒤 더 좋은 진입가를 고르는 것은 금지다.

## 2. 가격 기준

모든 가격은 `x(t) / F(t)`로 분할 정규화한다. F(t)는 t 이하에 실행된 분할만 곱한 누적 계수다. 보유 중에 분할이
있어도 한 포지션의 경로가 한 기준 위에 놓인다. 세션 t의 F(t)는 그 세션의 트레이더가 아는 정보이므로 PIT다.

## 3. 세션별 청산 순서

TP = E×(1+tp), SL = E×(1-sl). 진입 시 고정한다.

1. 그 종목의 봉이 없는 세션: 청산 불가, 다음 세션으로(`missing_sessions` 집계).
2. D+2부터: 시가 ≤ SL이면 **시가 청산**(SL_FIRST, gap). 아니고 시가 ≥ TP이면 **시가 청산**(TP_FIRST, gap. 걸어 둔
   지정가 매도가 더 좋은 시가에 체결).
3. 장중: 고가 ≥ TP이고 저가 ≤ SL이면 `AMBIGUOUS_SAME_BAR`. 저가 ≤ SL만이면 SL에 청산. 고가 ≥ TP만이면 TP에 청산.
4. D+1(진입 세션)은 시가가 곧 진입가라 갭 규칙이 없다. 장중 규칙만 적용한다.
5. D+10까지 안 닿으면 close(D+10) 청산(NEITHER).

### 동일 봉 모호성

| 처리 | 용도 |
| --- | --- |
| SL_FIRST로 간주, SL 가격에 청산, stop 비용 적용 | **Primary(보수)**. Gate 조건 1~5·8·9 |
| TP_FIRST로 간주, TP 가격에 청산 | 진단. INCONCLUSIVE 규칙에만 쓰고 PASS 근거로 쓰지 않음 |

### 거래 중단·상폐

- D+10에 봉이 없고 이후 다시 거래되면: 첫 거래 세션 시가에 청산. 그 시가가 SL 이하면 SL_FIRST gap, TP 이상이면
  TP_FIRST gap, 그 외 NEITHER(late).
- 이후 다시 거래되지 않으면: 마지막 종가 × (1 - 0.30)에 청산(delisted). 0%·100% haircut은 기술통계.
- 상폐·중단 종목을 표본에서 빼지 않는다.

## 4. 기업행위

C-M 계약을 그대로 쓴다.

- split_flag(D-20..D 분할) 또는 ca_suspect(D-19..D 3배 이상 점프)인 종목-날짜는 C-M0 적격에서 이미 빠진다(후보·통제 공통).
- `label_ca_suspect`: 정규화 후 open(D+1)/close(D), D+2..D+10의 close/prev close, open/prev close 중 하나라도 ≥3 또는
  ≤1/3이면 그 거래를 후보·통제 모두 제외하고 그룹별로 센다. 기록되지 않은 분할이 가짜 TP/SL을 만드는 것을 막는다.
- 이 제외가 진짜 폭락을 빼서 기대값을 부풀릴 수 있으므로, 후보의 제외 건을 min(시뮬레이션 수익, -sl - stop 비용)으로
  되돌려 넣은 스트레스를 기술통계로 보고한다.

## 5. 비용 `C_ATTACK_COST_V1`

프로젝트 공통 비용모델은 없다. Strategy E의 5~20bp 그리드는 $5 이상 universe 전용이고, 그 문서 스스로 저가 종목에
부족할 수 있다고 적는다. 그래서 새로 사전등록했다. 비용은 전부 close(D)에 알려진 값으로 정한다.

| 구성 | 왕복 |
| --- | ---: |
| 수수료 | 10bp |
| 스프레드+슬리피지, 가격 $3~5 | 60bp |
| 〃 $5~10 | 40bp |
| 〃 $10~20 | 25bp |
| 〃 $20 이상 | 15bp |
| ADV20 $5M~20M 추가 | 10bp |
| stop형 청산 추가(SL_FIRST, gap SL, 모호→SL) | 20bp |

범위는 유동성 좋은 $20 이상 TP 청산 25bp부터 $3~5 저유동 SL 청산 100bp까지다. 2배 비용은 기술통계. Gross는 진단용.
후보와 통제에 같은 규칙을 각자의 버킷과 청산 유형으로 적용한다.

## 6. 통제군

같은 신호일의 C-M0 적격 종목-날짜에서 **C-M0 후보 전부(모든 status)**를 뺀 모집단. 셀 = (날짜, 가격 버킷, ATR 버킷,
ADV 버킷). 거래 유효(진입봉 있음, label_ca_suspect 아님) 통제가 5개 이상인 셀만 매칭한다. 통제에도 같은 Exit·비용을
적용하고, 후보의 기준값은 그 셀 통제의 평균 net 수익이다.

## 7. 자본 모델

- 거래당 동일 명목.
- 슬리브 포트폴리오(H4 낙폭용): 자본 1.0, 비복리, 10개 슬리브. 각 신호일의 거래가 자본의 1/10을 균등 분할. 손익은
  청산 세션에 기록. 동시에 열린 코호트는 최대 10개이므로 총노출 ≤ 100%, 무한 자본 가정 없음.
- 공격형 포트폴리오 시뮬레이션(기술통계): H1·H2가 모두 통과할 때만. 자본 100, 복리, 거래당 위험 0.5%(명목 =
  0.005×자본/sl), 총노출 ≤ 자본. 사이징 탐색 없음.

## 8. PIT 감사 (실데이터, 코드 `run.pit_audit`)

| 검사 | 기대 |
| --- | --- |
| 차분: 벡터 시뮬레이터 == 스칼라 참조(D+1 이후 slice만 받음), 표본 400건 | 불일치 0 |
| 청산 이후 봉 전부 변조 | 결과 변화 0 |
| 양성대조: 진입 세션 저가를 1%로 | 대상 전부 결과 변화 |
| 같은 입력 2회 실행 | 거래표 digest 동일 |
| C-M0 후보표 | digest `64e57203…` 재현 |

스칼라 참조는 D+1부터의 배열만 받으므로 D 이전 정보가 들어갈 경로가 없다. 벡터 버전이 그와 일치하면 벡터 버전도
D 이전을 읽지 않는다.

## 9. M_ONLY 출처

C-E0 run `ce01-234478e8f7ff27570e13`의 `candidate_status.parquet`(A) 또는 동결 C-E0 코드로 EDGAR 저장소에서 다시 만든
status(B). 어느 쪽이든 (날짜, 종목) 집합이 C-M0 6,680행과 같고 status 건수가 C-E0 공표값과 정확히 같아야 한다.
아니면 `BLOCKED_M_ONLY_SOURCE`로 멈추고 거래를 하나도 시뮬레이션하지 않는다.

## 10. 실행 순서

1. 두 선언(C-M, C-ATTACK) checksum 확인
2. C 원시 → 패널 → C-M0 후보표 digest 재현
3. M_ONLY 출처 검증 (실패 시 BLOCKED)
4. 표본 조건 10 판정 (실패 시 INCONCLUSIVE, 수익 미계산)
5. PIT 감사·결정성
6. 5개 pair × 보수/낙관 시뮬레이션, 통제군 매칭, bootstrap
7. 민감도·기술통계, Gate
